# attila-mods

Personal Total War: ATTILA mods and tools for macOS (Apple Silicon, Feral port 1.6.1 from Steam). Personal use only; mods may require TWASE. Current project: unifying the region trading of Fireforged Empire and Region Trading Reloaded, see `docs/PLAN-region-trading.md` (status at the top).

## Layout

- `tools/twpack`: pack tool in Rust on `rpfm_lib` (pinned to RPFM tag `v5.1.1`, keep default features or it doesn't compile). Build with `cargo build --release`, binary `tools/twpack/target/release/twpack`. Commands (`--help` on each): `ls <pack> [pattern]`, `extract <pack> -o <dir> [pattern] [--raw]`, `db export <pack> [table] -o <dir>`, `db import <pack> <tsv>...`, `loc export <pack> -o <dir>`, `build <folder> -o <out.pack>`, `esf dump|check <file.esf | pack --path …>` (startpos / saves as an indented text tree, a round-trip check of twpack's own CAAB writer, which exists because rpfm_lib's is broken; see `docs/BUG-missing-building-slots.md`), `ui check|tree|render|export|import` (binary UI layouts <-> YAML text form `*.uic.yml`, which `build` also packs; `ui render` makes an HTML picture of a layout; see `docs/UI-FORMAT.md`). Patterns are case-insensitive prefixes or `*` globs. `--schema` defaults to `extracted/schemas/schema_att.ron`. rpfm_lib's `Container::extract` / `insert_file` silently fall back to binary on TSV errors, so twpack does TSV export / import itself.
- `mods/<name>/`: mods, each folder mirrors the game's `data/` root (so it deploys as loose files or builds into a pack with `twpack build`).
  - `mods/region_trading/`: the region trading mod (design: `docs/DESIGN-region-trading.md`, `DESIGN-region-value.md`, `DESIGN-federates.md`). `campaigns/<campaign>/mods/region_trading/scripting.lua` are stubs for TWASE's loader, the code is in `region_trading/` (`init.lua` entry, which switches on TWASE's native region deals with `twase.enable_region_trading`; `core.lua` shared table `rt` with `rt.log` / `rt.cm()`; `value.lua` the region value, tuned in `config.lua`; `governor.lua` protects governors on transfer; `compat/maga.lua` removes Fireforged's / RTR's `MAGA_EventHandler_*` listeners), the diplomacy layout in `ui/` and the names in `text/`. Built into `data/region_trading.pack` by `tools/deploy.sh region_trading` (`.build-pack`; UI layouts only load from packs; `play.sh` does it, the pack is in `tools/mod_list.txt`). `deploy.sh` also links built packs into Feral's `VFS/Local/local_mods/<mod>/`, so they show up in Feral's mod manager next to the Workshop items (switch and load order there; one folder per mod, a pack directly in `local_mods` is skipped). `--mods` (`play.sh`) loads an explicit list instead. Without Feral's launcher (`--skip-launcher`) Feral itself would ignore its load order and drop Workshop items whose details take over 1 s; TWASE's `FeralModOrder` hook fixes that (TWASE `docs/macos/addresses.md`). Console: `region_trading.explain(region_key[, faction_key])`. Logs go through `print` with the prefix `[region_trading]`.
  - `mods/fireforged_fixes/`: fixes for bugs in Fireforged Empire's scripts, patching its globals from a TWASE mod (review and reasons: `docs/REVIEW-fireforged-scripts.md`). Code in `fireforged_fixes/` (`init.lua` entry, one module per fix, `config.lua` switches), stub in `campaigns/main_attila/mods/fireforged_fixes/`. Inert without Fireforged. Built into `data/fireforged_fixes.pack` by `tools/deploy.sh fireforged_fixes` (`.build-pack`; `play.sh` does it, the pack is in `tools/mod_list.txt` after Fireforged's). Console: `fireforged_fixes.report()`. Tests: `lua tests/fireforged_fixes.lua` (real scripts from `extracted/`, stubbed `cm`).
- `tools/deploy.sh [--remove] [mod]`: copy a mod as loose files into the game's `data/` folder, or build it into `data/<mod>.pack` if it has a `.build-pack` file (or remove them). The dev harness `region_trading_dev` deploys loose. `tools/extract-all.sh`: see `extracted/`.
- `tools/play.sh [--no-deploy] [--feral-mods] [--latest | --load <save>]`: build the region_trading and fireforged_fixes packs and start the game through `twase-launch.command --skip-launcher` (main menu, newest save or a named one) with the mods in `tools/mod_list.txt` (without TWASE's `FeralModOrder` hook, Feral started without its launcher sometimes enabled no mods, and a modded save then crashed on load; unattended test launches should pass `--mods tools/mod_list.txt` too); warns if the dev harness is deployed. `tools/play-latest.command` is the double-click version (`play.sh --latest`), installed next to `twase-launch.command` in the game folder (copy it again after changing it).
- `extracted/`: unpacked game / mod content (`game/`, `fireforged/`, `rtr/`, made by `tools/extract-all.sh`) and `schemas/schema_att.ron` (from rpfm-schemas), **git-ignored, never commit it**. It is its own local git repo for diffing versions.

## TWASE (script extender, ~/GitHub/TWASE, Windows and macOS in one repo, version 1.1.0)

- Since 2026-10-12 the macOS code lives in `~/GitHub/TWASE` (rfuzzo/TWASE) under `src/platform/macos/` (`dylib/`, `sdk/`, `launcher/twase-launch.command`), Windows under `src/platform/win32/`. The old repo `~/GitHub/twase_macos` (rfuzzo/twase_macos) is retired, don't commit there. Region trading is on `main` (`src/platform/macos/dylib/Hooks/NativeRegionTrading.cpp`, `dylib/Scripting/LuaApi.cpp`). Build with `xmake -y` in `~/GitHub/TWASE` (installs into the game; only while the game is closed). For larger TWASE work use a branch. The shared code is moving into `src/core/`, so paths there may change.

- Start the game with `<game folder>/twase-launch.command [--skip-launcher] [--mods <Runcher-style mod_list.txt>] [--load "<save>.save"]`. The game ignores process arguments on macOS; the launcher sets Feral's preferences for one launch and links packs from the Workshop into `TotalWarAttilaData/data`. Steam must be running.
- In-game Lua console: key below Esc. Commands run on the game's Lua thread. Game Lua output goes to the console and `TWASE/logs/` (Lua lines need `logging.level = "debug"` or lower in `TWASE/config.ini`). The global `cm` is nil there: use `get_cm()` (the instance; `campaign_manager` is only the class).
- Mod loader: every `campaigns/<campaign>/mods/<name>/scripting.lua` is `require`d after the campaign's `scripting.lua`, from loose files in `TotalWarAttilaData/data/` or from a loaded pack. Feral's user `maps` folder is wiped on every launch, don't use it.
- The user tests interactively and quits the game themselves; unattended test launches should close the game when done.

## Reverse engineering

- Binary Ninja 6.0 (Free) on the Mach-O `Total War ATTILA.app/Contents/MacOS/Total War ATTILA`, bndb at `<game folder>/Total War ATTILA/Total War ATTILA.bndb`. The GUI MCP server (http://127.0.0.1:24642/mcp, when started in BN) can decompile and rename, but renaming functions with many callers is slow.
- Known addresses (unslid, base `0x100000000`), incl. the diplomacy deal evaluator `0x101d7b25c`: `~/GitHub/TWASE/docs/macos/addresses.md`.
- The binary has two Lua 5.1 copies; the game's is at `0x103f…`.

## Mod facts so far

- Both mods ship the same `maga\*` script paths (Fireforged has its own modified copy plus `maga\script\ui\regionTrading.lua` and `ui\bin\button\trade_region`) and both replace `campaigns\<campaign>\scripting.lua`, so whichever pack has priority silently replaces the other.
